A production pattern taxonomy

The earlier page grouped ReAct, plan-and-execute and reflection as “thinking styles.” A more useful 2026 taxonomy separates patterns by the system problem they solve: action, routing, persistence, verification, delegation and authorization.

Action

Tool loop

Model selects a typed tool and uses the observable result as the next input.

Planning

Planner / executor

Plan once or incrementally, then execute bounded steps with checkpoints and revision.

Routing

Router / specialists

Classify the request and invoke a specialist model, knowledge source, workflow or agent.

Quality

Validator / repair

Check output against schema, evidence or policy and repair before acceptance.

State

Durable graph

Persist workflow state so runs can pause, retry, resume and survive process restarts.

Control

Approval gate

Interrupt high-risk actions and resume only after an authorized decision.

Scale

Subagents

Delegate context-isolated work to specialists and return structured artifacts.

Collaboration

Handoff

Transfer responsibility from one state or specialist to another with explicit ownership.

Efficiency

Budgeted execution

Limit model calls, tool calls, wall time and cost; stop or escalate when the budget is exhausted.

What “reflection” should mean in production

Prefer observable validation over hidden introspection

A production system can ask a model to critique an artifact or plan, but observability should capture the artifact, criteria, validator result and decision: not hidden chain-of-thought. This makes the workflow auditable and easier to regression-test.

DraftInitial answer, plan, code or artifact.
CheckSchema, policy, evidence, tests or rubric.
RepairTargeted revision based on observable failures.
Accept / escalateDeterministic gate or authorized human decision.

Decision rules

Use a graph when…you need explicit state, retries, branching, checkpoints or approvals.
Use multiple agents when…specialization, context isolation or parallelism creates measurable gains.
Use deterministic code when…the rule is known, stable and high-impact. Do not ask a model to rediscover policy.

Frequently asked questions

Should I start with ReAct?

For a simple tool-use task, a model-plus-tools loop is often enough. As requirements grow, add explicit graphs, validators, persistence and approvals rather than assuming a more autonomous pattern.

What is a durable agent workflow?

A durable workflow persists state at checkpoints so it can resume after failures or human pauses instead of restarting from the beginning.
