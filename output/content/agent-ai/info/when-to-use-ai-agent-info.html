The litmus test

Five gates before you say “agent”

A useful agent needs more than a strong model. It needs a goal, context, a reason to choose among actions, safe tools, and a measurable outcome.

1

Goal

Can you describe the desired outcome more clearly than the exact steps?

2

Context

Can the system access trusted data and enough state to make informed decisions?

3

Choice

Does the path vary enough that dynamic planning is better than a fixed workflow?

4

Action

Can tools and permissions be scoped so the agent can act without excessive blast radius?

5

Evaluation

Can you measure completion, quality, safety, cost and escalation behavior?

Green lights

Where agents tend to help

🔎

Research + synthesis

Gather information from many sources, compare evidence, produce a structured recommendation and keep traceable citations.

🧰

Tool-rich operations

Use APIs, databases, files, tickets, CRM or internal systems where the next action depends on what the system observes.

🔁

Exception-heavy workflows

Handle normal cases quickly while reasoning through edge cases and escalating ambiguous or high-risk cases.

🕒

Long-running tasks

Maintain durable state, pause for review, resume after approval, and coordinate work across multiple steps.

Red flags

Where agents are often overkill

📏

Stable rules

If the decision can be written as reliable deterministic logic, keep the workflow deterministic and use AI only where it adds clear value.

🚨

Irreversible risk

When a single wrong action has severe consequences, use approval gates, narrow permissions and independent verification.

🌫️

Missing data

Do not use autonomy to hide weak foundations. Fix grounding, data quality, ownership and access first.

❔

No success metric

If the team cannot define what better means, there is no safe way to tune the agent or justify more autonomy.

Operating model

Autonomy should rise with evidence

Start small, collect evidence, then expand. The safest agent roadmap is an experiment loop, not a one-time launch.

1. Assist

Recommend but do not act. Measure usefulness and failure modes.

2. Act with approval

Prepare actions and require human confirmation for material steps.

3. Bounded autonomy

Allow low-risk actions within explicit limits and with full observability.

4. Expand selectively

Increase autonomy only for paths that show stable quality, safety and business benefit.
