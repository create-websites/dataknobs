The current LangChain agent model

The older page used AgentExecutor, legacy memory classes and model-specific wrappers as the center of the architecture. Current LangChain documentation centers simple agents on create_agent: a model calling tools inside a configurable harness of prompt, tools, middleware and state. LangChain agents use LangGraph primitives underneath; move directly to LangGraph when you need explicit control over nodes, routing, persistence and interrupts.

Framework boundary

LangChain is the fast path for common agent loops. LangGraph is the lower-level orchestration layer when your workflow needs durable execution, explicit state transitions, retries, approvals or custom routing.

A production lifecycle

1 · Define mandateScope outcome, non-goals, owner and examples.
2 · Model the workflowDocument human process, exceptions and approval points.
3 · Build a thin harnessModel + typed tools + system policy.
4 · Add stateCheckpoints and memory only where required.
5 · Add controlsIdentity, scopes, middleware, human approval and budgets.
6 · EvaluateTask success, tool trajectory, cost, latency and safety.
7 · Deploy graduallyObserve, regress, roll out and maintain rollback.

Minimal current agent

from langchain.agents import create_agent
from langchain.tools import tool

@tool
def lookup_customer(customer_id: str) -> str:
    """Return the approved customer summary for a customer ID."""
    return "..."

agent = create_agent(
    model="openai:gpt-5.5",
    tools=[lookup_customer],
    system_prompt=(
        "Resolve support requests. Never modify an account unless "
        "the workflow has explicit approval."
    ),
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "Review customer 123"}]
})

The model identifier follows current documentation. Replace it with a model available in your environment and keep tool authority narrower than model capability.

State and persistence

For multi-turn or interruptible workflows, use a checkpointer and a stable thread ID. An in-memory saver is appropriate for local examples; production systems should use a persistent store suited to their deployment.

from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

agent = create_agent(
    model="openai:gpt-5.5",
    tools=tools,
    checkpointer=InMemorySaver(),
)

config = {"configurable": {"thread_id": "case-123"}}
agent.invoke({"messages": [{"role": "user", "content": "Start review"}]}, config=config)

What to evaluate

OutcomeDid the workflow accomplish the business task correctly?
Tool behaviorCorrect tool, arguments, sequence, unnecessary calls and side effects.
StateWas the right context retained, and was sensitive state excluded or expired?
ControlWere policy gates, approvals and authorization decisions respected?
OperationsLatency, cost, retries, timeouts and recoverability.
Do not make hidden chain-of-thought your observability strategy. Trace model calls, tool calls, state changes, validators, approval events, artifacts and outcomes instead.

When to move to LangGraph

Pause / resumeHuman approval or user input must suspend a workflow and resume later.
Explicit control flowNodes, retries, recovery paths and routing need to be inspectable.
Durable long-running workState must survive process restarts, failures or long delays.

Frequently asked questions

Is AgentExecutor still the recommended starting point?

Current LangChain documentation centers simple agents on create_agent. Older AgentExecutor examples may still appear in legacy integrations, but new production guides should use the current API surface.

When should I use LangGraph directly?

Use LangGraph when you need explicit workflow state, durable execution, branching, retries, human interrupts, subgraphs or control over each transition.
