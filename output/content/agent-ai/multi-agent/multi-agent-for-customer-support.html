Architecture first

Use multiple agents only when specialization improves the workflow

A support system does not need one agent per step. Start with one bounded support agent, then split roles when tool permissions, data boundaries, evaluation criteria, or parallel work genuinely differ.

Bounded specialists

A production support team needs clear authority, not just clever prompts

↪

Triage agent

Classifies intent, detects high-risk categories, extracts entities and chooses the next workflow. It should not issue refunds or modify accounts.

⌕

Context agent

Retrieves approved knowledge, customer history and relevant product state with provenance and tenant-aware access controls.

✓

Resolution agent

Drafts an answer or invokes a narrow action such as reset, update or refund within explicit policy and value limits.

⚑

Escalation / QA

Routes ambiguous, regulated, angry or high-value cases to humans and packages the context so the customer does not repeat the story.

End-to-end case flow

Design the ticket journey as a controlled state machine

1

Intake

Normalize channel, identity and case context.

2

Route

3

Ground

4

Resolve

5

Verify

Check evidence, tone, policy and outcome.

6

Learn

Capture outcome and evaluation feedback.

KNOBS

Measure resolved outcomes, not demo fluency

Quality

Resolution correctness, groundedness, policy adherence and hallucination rate.

Operations

First-response latency, time-to-resolution, containment rate and escalation precision.

Business

CSAT, repeat-contact rate, cost per resolved case and agent productivity.
