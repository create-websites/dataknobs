Select a pattern by control-flow need

Do not choose a pattern because it sounds more autonomous. Choose it because it solves a specific control-flow problem with acceptable cost, failure behavior and governance.

Tool-use loop

How it works: Model chooses among typed tools, observes results and iterates.

Best for: Focused research, lookup, support and data tasks.

Production note: Bound tool schemas, call budgets, retries and result validation.

Pattern catalog

01 · Act

Tool-use loop

Pick and invoke a bounded tool, inspect the observable result, then decide the next step.

02 · Plan

Planner → executor

Separate planning from execution when long horizons or independent plan evaluation matter.

03 · Route

Router → specialist

Route requests to the right model, source or agent instead of giving every agent every tool.

04 · Verify

Generate → validate → repair

Make acceptance explicit; use schema, business rules, groundedness checks or human review.

05 · Approve

Human-in-the-loop

Pause and resume durable workflows around high-impact or ambiguous decisions.

06 · Delegate

Supervisor + subagents

Parallelize and isolate specialist work when the benefit outweighs coordination complexity.

Frequently asked questions

What is the best agentic design pattern?

There is no single best pattern. Start with the smallest control-flow pattern that can satisfy the task, then add routing, persistence, validation, approvals or multiple agents only when measurements justify them.

Is multi-agent more reliable than a single agent?

Not automatically. Multi-agent systems add specialization and isolation but also create coordination, attribution, latency and security overhead.
