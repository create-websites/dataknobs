5 Stage Gates for agentic development

Human time belongs at gates and escalations, not inside repetitive build loops. The ADLC uses five named checkpoints where human judgement approves direction, accepts risk, and authorizes release.

Where humans hold the line

Every gate has a human owner, explicit criteria, and a fail state. If the criteria are not met, work returns to the prior stage with evidence-backed feedback.

Detailed checkpoints

Five gates, five accountable owners

The ADLC keeps agents moving quickly inside execution loops while concentrating human review at the highest-leverage decision points.

Gate 01🎯Product Owner

Intent Lock

Before specification begins, the Product Owner confirms the team is solving the right problem. Ambiguous intent causes downstream specs, plans, and builds to drift.

✓Problem statement is clear and unambiguous.
✓Success criteria are measurable.
✓Scope defines what is included and excluded.
✓Stakeholders confirm the framing.
Gatekeeper
Product OwnerOwns user value and problem framing.
Pass condition
PO sign-off recorded
If gate fails
Return to Stage AAgent revises problem framings and resolves ambiguity.
Gate 02📐Tech Lead

Spec Approval

The Tech Lead ensures requirements are precise enough for agents to execute and for gates to verify. Vague requirements create plausible but wrong outputs.

✓Requirements are precise, with no scope ambiguity.
✓Acceptance criteria are testable.
✓Edge cases are documented.
✓Technical, legal, and operational constraints are captured.
Gatekeeper
Tech LeadOwns technical feasibility and requirement quality.
Pass condition
Criteria testable, TL sign-off recorded
If gate fails
Return to Stage BAgent regenerates criteria around the identified gaps.
Gate 03✅Sponsor

Plan Authorization

Before execution, the Sponsor approves the task graph, dependencies, resource commitment, autonomy levels, and guardrails that bound agent action.

✓Task graph is complete with dependencies mapped.
✓Effort estimates are acceptable.
✓Guardrails are explicit and documented.
✓Autonomy level is approved for each task category.
Gatekeeper
SponsorOwns resource allocation and risk boundaries.
Pass condition
Plan and guardrails approved
If gate fails
Return to Stage CAgent revises the task graph or guardrail proposal.
Gate 04🔍QA

Verification Sign Off

QA reviews the evidence package, agent decisions, known failure modes, and risk posture. Passing tests alone is not sufficient for release readiness.

✓All acceptance criteria tests have passed.
✓Agent decisions during execution are reviewed.
✓Known failure modes and residual risks are documented.
✓Risk acceptance is explicit, not implicit.
Gatekeeper
QAOwns evidence quality and risk acceptance review.
Pass condition
Evidence reviewed, QA sign-off recorded
If gate fails
Return to Stage EAgent re-verifies around the identified gaps.
Gate 05🚀Eng Manager

Release Authorization

The Engineering Manager authorizes production release only after deployment sequencing, monitoring, rollback, and on-call coverage are confirmed.

✓Deployment sequencing is confirmed and documented.
✓Monitoring and alerting are configured and tested.
✓Rollback procedure is rehearsed and ready.
✓On-call coverage is confirmed for the release window.
Gatekeeper
Engineering ManagerOwns production readiness and final release accountability.
Pass condition
EM sign-off recorded
If gate fails
Deployment haltedAgent creates a remediation plan before reauthorization.

The core insight

Human attention is a governance asset

In agentic development, human review should not be spread thin across every micro-decision. Gates concentrate judgement where it changes outcomes.

Inside build loops
Agent-owned
~10%
At stage gates
Primary human investment
~65%
On escalations
Edge cases
~25%

“A gate is where human responsibility becomes explicit. Without named gatekeepers and clear criteria, oversight is theater. With them, oversight becomes governance.”

Prashant Dhingra, Agentic Development Lifecycle Framework

Why it works

Why gates outperform continuous oversight

Gates let agents move fast without removing human accountability.

🎯

Focused, not diluted

Human attention is applied to the five decisions that matter most instead of thousands of agent micro-decisions.

⚡

Agents run at full speed

Agents execute, test, and self-correct within each stage without waiting for constant human review.

🔒

Accountability is explicit

Each gate has a named owner, making approval responsibility clear and auditable.

🔁

Failure is bounded

When a gate fails, work returns to the prior stage with specific evidence-backed gaps.

📋

Audit trail built in

Every gate sign-off becomes a documented decision point for regulated and enterprise environments.

🧩

Works with SDLC

Gates complement sprint review, PR review, release readiness, and existing engineering governance.
